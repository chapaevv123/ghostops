# User guide

1. Run `npm.cmd run dev` and open the local address. Choose **New investigation**, enter a title and optional description. The Investigations screen can search saved titles, descriptions, and statuses.
2. Choose **Import evidence** and select local `.log`, `.txt`, `.json`, or `.jsonl` files. Files are checked before reading against the 50 MB limit; at most 20 files can be selected together. Reading reports byte progress and can be cancelled. A file with a duplicate name in the same investigation is rejected to keep source references unambiguous; duplicate lines within a file are retained and counted. Saved-investigation analysis runs in a Worker with a stage indicator and a Cancel control. If cancellation happens after a save commits, check the investigation list before retrying. Invalid UTF-8 is rejected. Open **Import summary** on Overview for read, recognized, raw, retained, rejected, duplicate, and unresolved-time counts. Rejected JSONL lines and reasons are retained in the local report; when any are rejected the summary opens automatically.
3. Review **Timeline**. Direct source records have readable titles; click an event to inspect its original text, file name, line, and byte offset. Use classification filters and search. Unknown timestamps are labelled.
4. Open **Investigation Graph**. Drag the background to pan, use mouse wheel or controls to zoom, choose Fit/Reset, filter nodes or links, and select a node or link. Selecting a hypothesis highlights its immediate evidence and related observations; the detail area explains each relationship. Solid source links and dashed timing, correlation, or possible-explanation links have different meanings. The legend and text relationship list remain available. Tab reaches nodes and links; arrow keys move between graph nodes. On narrow screens, swipe horizontally inside the graph to see all columns.
5. Compare **Hypotheses**. Each card shows its supporting and contradicting evidence, missing records, next diagnostic steps, and status. Hypotheses are suggestions, not conclusions.
6. Add **Notes** or **Manual Findings**. A selected evidence item or timeline claim is linked to a new entry. Manual findings remain separate from machine-verified claims.
7. Change status on **Overview**. Rename, duplicate, archive, or delete there. Deletion requires confirmation.
8. Review the three separate statuses in **Integrity & Export**. Analysis replay checks reproducibility; Data integrity checks saved hashes, source offsets, links, and counts when run; Source authenticity remains UNAVAILABLE because a local hash cannot establish who created an external log. Run **Integrity Check**, then export a portable package and store backups outside the browser profile. Importing a package rechecks its contents before saving. Markdown is a readable report; V1 JSON session export remains available for compatibility.

Three built-in scenarios can be opened from the sidebar. They are marked DEMO DATA and are ephemeral until saved as a new investigation. Imported files and saved investigations are marked USER DATA. See [persistence](data-persistence.md) and [privacy](privacy-and-security.md) before using sensitive incident records.
